# Руководство по обучению модели TRM

## Как работает обучение модели

### 1. Архитектура обучения

Модель TRM использует **рекурсивное рассуждение** с механизмом **ACT (Adaptive Computation Time)**:

#### Рекурсивное рассуждение:
- Модель имеет два уровня: **H (высокий)** и **L (низкий)**
- На каждом шаге:
  1. **L-циклы** (по умолчанию 6): обновляет латентное состояние `z_L` на основе `z_H + входные данные`
  2. **H-цикл** (1 раз): обновляет латентное состояние `z_H` на основе `z_L`
- Это повторяется **H_cycles** раз (по умолчанию 3)
- Большинство циклов выполняется **без градиентов** (для экономии памяти), только последний цикл с градиентами

#### ACT (Adaptive Computation Time):
- Модель может выполнять разное количество шагов для разных примеров в батче
- Использует Q-learning для принятия решения об остановке
- Максимальное количество шагов: `halt_max_steps` (по умолчанию 16)
- Модель обучается предсказывать, когда остановиться

### 2. Процесс обучения одного батча

```python
# 1. Инициализация состояния переноса (carry)
carry = model.initial_carry(batch)  # Содержит z_H, z_L, steps, halted

# 2. Прямой проход через модель
carry, loss, metrics, _, _ = model(carry=carry, batch=batch)

# 3. Вычисление градиентов
loss = loss / global_batch_size  # Нормализация на размер батча
loss.backward()

# 4. Синхронизация градиентов (при распределенном обучении)
if world_size > 1:
    dist.all_reduce(gradients)

# 5. Обновление весов
optimizer.step()
optimizer.zero_grad()
```

### 3. Особенности обучения

#### Оптимизаторы:
- **AdamATan2** для основных весов модели
- **SignSGD** для разреженных эмбеддингов головоломок (puzzle embeddings)
- Разные learning rates для разных компонентов

#### Расписание learning rate:
- **Cosine schedule с warmup**
- Warmup steps: 2000 (по умолчанию)
- Минимальное отношение: 1.0 (по умолчанию)

#### Потери:
- **Language modeling loss** (stablemax_cross_entropy или softmax_cross_entropy)
- **Q-halt loss** (binary cross-entropy для предсказания остановки)
- **Q-continue loss** (опционально, для бутстраппинга)

### 4. Эффективность памяти

#### Оптимизации:
- **bfloat16** для прямого прохода (forward_dtype)
- Большинство рекурсивных циклов выполняется **без градиентов** (torch.no_grad)
- **Memory-mapped файлы** для больших датасетов
- **Gradient checkpointing** не используется, но можно добавить

#### Использование памяти:
- Модель: ~7M параметров × 2 bytes (bfloat16) ≈ **14 MB** для весов
- Градиенты: ~7M × 4 bytes (float32) ≈ **28 MB**
- Оптимизатор (Adam): ~7M × 8 bytes ≈ **56 MB**
- **Итого для модели: ~100 MB**

Основное потребление памяти идет на:
- **Активации** во время прямого прохода
- **Состояния переноса** (carry) для каждого примера в батче
- **Входные данные** и эмбеддинги

## Можно ли обучить на 16GB GPU?

### ✅ ДА, но с ограничениями

Согласно README:
- **Sudoku-Extreme**: рекомендуется 1 L40S (48GB), но можно попробовать на 16GB
- **Maze-Hard**: можно запустить на 1 GPU с уменьшенным batch_size (128 вместо 768)
- **ARC-AGI**: требует 4 H-100 GPU (80GB каждый), но можно попробовать на меньших GPU с уменьшенным batch_size

### Рекомендации для 16GB GPU:

#### 1. Уменьшить batch_size:
```bash
# Вместо global_batch_size=768
global_batch_size=64  # или даже 32
```

#### 2. Использовать gradient accumulation:
В текущем коде нет встроенного gradient accumulation, но можно модифицировать:
- Накопить градиенты за несколько мини-батчей
- Обновить веса только после накопления

#### 3. Уменьшить количество циклов:
```bash
arch.H_cycles=2  # вместо 3
arch.L_cycles=4  # вместо 6
```

#### 4. Уменьшить размер модели:
```bash
arch.hidden_size=256  # вместо 512
arch.num_heads=4      # вместо 8
```

#### 5. Использовать gradient checkpointing:
Можно добавить `torch.utils.checkpoint` для экономии памяти

#### 6. Обучать на более простых датасетах:
- Начните с **Sudoku-Extreme** (самый простой)
- Затем попробуйте **Maze-Hard**
- **ARC-AGI** требует больше памяти

### Пример конфигурации для 16GB GPU:

```bash
run_name="pretrain_sudoku_16gb"
python pretrain.py \
arch=trm \
data_paths="[data/sudoku-extreme-1k-aug-1000]" \
evaluators="[]" \
epochs=50000 eval_interval=5000 \
lr=1e-4 puzzle_emb_lr=1e-4 weight_decay=1.0 puzzle_emb_weight_decay=1.0 \
global_batch_size=32 \  # Уменьшено с 768
arch.mlp_t=True arch.pos_encodings=none \
arch.L_layers=2 \
arch.H_cycles=2 \  # Уменьшено с 3
arch.L_cycles=4 \  # Уменьшено с 6
arch.hidden_size=256 \  # Уменьшено с 512 (опционально)
+run_name=${run_name} ema=True
```

**Оценка времени выполнения:**

### Анализ изменений:

1. **Batch size: 768 → 32** (в 24 раза меньше)
   - Количество шагов увеличится в **24 раза**
   - Время на один шаг уменьшится примерно в **20-24 раза** (меньше данных обрабатывать)

2. **H_cycles: 3 → 2** (на 33% меньше)
   - Время на шаг уменьшится примерно на **15-20%**

3. **L_cycles: 6 → 4** (на 33% меньше)
   - Время на шаг уменьшится примерно на **15-20%**

4. **hidden_size: 512 → 256** (в 2 раза меньше, опционально)
   - Если используется: время на шаг уменьшится примерно в **2 раза**

### Расчет времени:

**Базовое время (оригинальная конфигурация):**
- < 20 часов на L40S (48GB, мощная GPU)

**С учетом изменений:**

**Вариант 1: Без уменьшения hidden_size (512)**
- Количество шагов: ×24 (из-за меньшего batch_size)
- Время на шаг: ÷20 (меньший batch) × 0.8 (меньше циклов) ≈ ÷16
- **Итоговое время: 20 часов × (24/16) ≈ 30-35 часов**

**Вариант 2: С уменьшением hidden_size (256)**
- Количество шагов: ×24
- Время на шаг: ÷20 × 0.8 × 0.5 (меньший hidden_size) ≈ ÷8
- **Итоговое время: 20 часов × (24/8) ≈ 60 часов**

**Вариант 3: На более слабой GPU (16GB, например RTX 3060/3070)**
- Производительность GPU примерно в **2-3 раза ниже** L40S
- **Итоговое время: 60-100 часов** (с hidden_size=256)
- **Итоговое время: 30-50 часов** (без уменьшения hidden_size)

### Рекомендации:

**Для 16GB GPU (RTX 3060/3070/4060):**
- **С hidden_size=256**: ~60-80 часов (2.5-3.5 дня)
- **Без уменьшения hidden_size**: ~30-40 часов (1.5-2 дня), но может не поместиться в память

**Для более мощной 16GB GPU (RTX 3080/4070):**
- **С hidden_size=256**: ~40-60 часов (1.5-2.5 дня)
- **Без уменьшения hidden_size**: ~20-30 часов (1-1.5 дня)

**Оптимизация времени:**
- Можно уменьшить `epochs` до 30000-40000 вместо 50000
- Можно увеличить `eval_interval` до 10000, чтобы реже делать оценку
- Можно отключить `ema=True` для небольшого ускорения

### Пример оптимизированной конфигурации:

```bash
# Быстрее, но может быть немного хуже качество
epochs=30000 eval_interval=10000 \
global_batch_size=32 \
arch.H_cycles=2 arch.L_cycles=4 \
arch.hidden_size=256 \
ema=False  # Отключить EMA для ускорения
```

**Ожидаемое время: ~40-50 часов** на среднем 16GB GPU

**Да, можно обучить на 16GB GPU**, но нужно:
1. Уменьшить `global_batch_size` до 32-64
2. Возможно, уменьшить количество циклов H/L
3. Начать с более простых датасетов (Sudoku, Maze)
4. Мониторить использование памяти и корректировать параметры

Модель сама по себе очень маленькая (7M параметров), основное ограничение - это размер батча и количество рекурсивных циклов.
